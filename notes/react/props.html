Props: data passed in

2 min read No experience needed
💡
In plain English
Props are the arguments you hand a function, and they work exactly like a job order given to a workshop. The order says “a blue chair, seat height 45cm”; the workshop builds to the order and does not get to change it. If a different chair is wanted, a new order is sent — the workshop never edits the one it was given.

A component takes arguments, called props. They arrive as one object, and are almost always destructured in the parameter list so the names are visible at the top of the function.

jsProps in, markup out
function SaveButton({ label, disabled, onSave }) {
  return (
    <button className="s-btn" disabled={disabled} onClick={onSave}>
      {label}
    </button>
  );
}

<SaveButton label="Save draft" disabled={false} onSave={handleSave} />

Two rules make props predictable, and both are non-negotiable:

  • Props are read-only. A component never writes to its own props. If a value needs to change, it belongs to whoever passed it — which is why buttons receive an onSave function instead of changing anything themselves.
  • Data flows down. Parent to child, one direction. A child talks back by calling a function its parent gave it. This is the whole reason a React screen is traceable: when a value is wrong, there is exactly one place it can have come from.
Props

Given by the parent. Read-only. Change them and React cannot know who is responsible for the value.

State

Owned by this component. Changing it is what causes a redraw.

Handler prop

A function passed down so a child can ask the parent to change something.

Children

Whatever was written between the tags. How wrappers stay ignorant of what they wrap.

children is the one prop with special syntax: whatever you put between the opening and closing tags arrives as props.children. It is how wrappers — cards, dialogs, layouts — are written.

jschildren: a wrapper that does not care what it wraps
function Card({ title, children }) {
  return (
    <div className="s-card p-4">
      <h3>{title}</h3>
      {children}
    </div>
  );
}

<Card title="Billing">
  <p>Anything at all goes here.</p>
</Card>
A child component receives count as a prop and wants to increase it. Why can it not just do count = count + 1?Answer

Because the child does not own that value — the parent does. Changing it in the child would change a copy, so the parent, and every other component reading the same value, would carry on showing the old one. The screen and the data would disagree, which is exactly what React exists to prevent.

The fix is for the parent to pass down a function as well: the child calls onIncrement(), and the parent — which owns the value — does the changing. Data flows down, events flow up.
