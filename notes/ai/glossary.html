The jargon, decoded

3 min read No experience needed
💡
In plain English
The vocabulary, in one place. Much of the difficulty in this field is terminology rather than concept — the ideas are usually simpler than the words used for them, and once a term is decoded it often turns out you already understood the thing.

Every term you will meet in a meeting about this, in one place. Nothing here is new — it is the vocabulary of the sections above, collected so this page can be used as a reference once it has been read as a lesson.

TermWhat it means
TokenA piece of a word. The unit of both billing and every size limit. Roughly 750 English words per 1,000 tokens.
Context windowThe total tokens one request may contain — instructions, history, documents, question and answer.
Parameters / weightsThe numbers learned during training. "70B" means seventy billion of them. More is usually more capable and more expensive to run.
TransformerThe architecture behind current models. Attention is its central mechanism.
Pre-training / fine-tuningLearning language from an enormous corpus; then adjusting on a smaller, targeted set.
RLHFReinforcement learning from human feedback — the tuning that makes a raw model behave like a helpful assistant.
TemperatureHow random the next-token choice is. Low is focused and repeatable.
Extended thinking / reasoningThe model working through a problem internally before answering. Better on hard tasks, more tokens.
System promptThe instructions, sent separately from the user’s messages.
Few-shotIncluding examples of the input and the output you want.
Chain of thoughtAsking for the steps rather than only the conclusion.
Structured outputConstraining the reply to a schema so a program can parse it safely.
Prompt cachingReusing a stable prefix across calls at a fraction of the cost.
HallucinationA confident, fluent, invented answer. Not lying — the model cannot tell.
GroundingTying an answer to supplied sources, and citing them.
EmbeddingText as a list of numbers positioned by meaning.
Vector database / pgvectorStorage that finds the nearest embeddings quickly. pgvector does it inside PostgreSQL.
Cosine similarityThe usual measure of how close two embeddings are.
ChunkingSplitting documents into retrievable passages. The most under-rated decision in RAG.
Hybrid searchSemantic search plus keyword search, combined. Usually the biggest single quality win.
RerankingA second, sharper pass that re-orders retrieved candidates by relevance.
RAGRetrieval-augmented generation: retrieve the relevant passages, then answer from them.
Tool use / function callingThe model requests an action; your code decides whether to run it.
AgentA loop where the model repeatedly acts, observes and decides until a task is done.
MCPModel Context Protocol — a standard way to expose tools and data to a model.
Prompt injectionText that a model reads as an instruction when it was meant as data. The central security problem.
JailbreakGetting a model to ignore its safety training.
GuardrailsChecks around a model — input filters, output validation, allowed-action lists.
EvalA test set of inputs with expected outputs, run on every prompt change.
LLM-as-judgeUsing a model to grade output against a rubric, so evaluation scales.
InferenceRunning a trained model to get an answer. Your ongoing cost.
QuantisationShrinking a model’s numbers so it runs on smaller hardware, trading a little quality.
Open weightsA model you can download and run yourself, as opposed to calling an API.
MultimodalAccepting more than text — images, PDFs, audio.
Batch APIAsynchronous processing at lower cost, for work nobody is waiting on.
