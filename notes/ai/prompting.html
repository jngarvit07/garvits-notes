Prompting that actually works

2 min read No experience needed
💡
In plain English
A prompt is a brief, and it is judged by the standard you would apply to briefing a capable new colleague who cannot ask you a follow-up question. Say what the job is, who it is for, what the output should look like, and show an example. Almost every “prompt technique” with a name is a formalisation of something you would already do when writing clear instructions for a person.

A prompt is a specification. Most bad output is an under-specified request rather than an incapable model, and the fixes are unglamorous.

TechniqueWhat it isUse when
Be specific about the outputSay the format, the length, the audience, and what to do when unsure.Always. This is the highest-value change available.
Give examples (few-shot)Two or three input/output pairs showing exactly the shape you want.The format matters more than the prose — extraction, classification, consistent tone.
Let it reasonAsk for step-by-step work, or enable extended thinking.Anything with more than one step: analysis, planning, maths, debugging.
Structured outputConstrain the reply to a schema so it is valid JSON every time.Whenever a program, not a person, reads the answer.
Give it an out"If the context does not contain the answer, say you do not know."Always. Without permission to refuse, a model will invent something.
Prompt cachingMark a long stable prefix as cacheable so it is not re-charged in full each call.A large system prompt or document reused across many requests.
Not this · vague
Summarise this feedback.
Do this · specified
Summarise this customer feedback in at most three bullets.
Each bullet: the concrete problem, no adjectives, no advice.
Ignore praise. If there is no actionable problem, reply
exactly: NO ISSUES.

Prompt caching is the one cost technique worth knowing early. A long set of instructions or a reference document sent on every request can be cached by the provider, so repeat calls pay a small fraction for that prefix. It matches on an exact prefix, which has one practical consequence: put the stable content first and the varying content last. A timestamp at the top of a system prompt silently defeats the entire cache.

jsCaching a long prefix
const response = await client.messages.create({
  model: 'claude-opus-5',
  max_tokens: 16000,
  system: [
    {
      type: 'text',
      text: LONG_STABLE_INSTRUCTIONS,     // identical on every call
      cache_control: { type: 'ephemeral' },
    },
  ],
  messages: [{ role: 'user', content: question }],   // the varying part, last
});

// Prove it is working:
console.log(response.usage.cache_read_input_tokens);   // zero every time = a cache miss
Your prompt says “summarise this professionally” and the results are inconsistent. What is the actual problem?Answer

“Professionally” is not an instruction, it is a hope. It means different things in different industries and the model has no way to pick yours.

Replace the adjective with the specification you actually have in mind: how long, for whom, in what person, what to leave out, and one example of a summary you consider correct. Inconsistent output is almost always an underspecified brief rather than a weak model.
