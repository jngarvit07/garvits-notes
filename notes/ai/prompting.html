Prompting that actually works

2 min read No experience needed
💡
In plain English
A prompt is a set of instructions, and you should judge it the way you would judge instructions given to a smart new joinee who cannot come back and ask you a doubt. Say what the job is, who it is for, what the answer should look like, and show one example. Almost every "prompting technique" with a fancy name is just a formal version of something you would already do while writing clear instructions for a person.

A prompt is a specification. Most bad output comes from a half-written request, not from a weak model, and the fixes are boring.

TechniqueWhat it isUse when
Be exact about the outputSay the format, the length, who will read it, and what to do when unsure.Always. This one change gives you the most improvement.
Give examples (few-shot)Two or three input/output pairs showing exactly the shape you want.When the format matters more than the writing — pulling out fields, sorting, keeping a consistent tone.
Let it thinkAsk for step-by-step working, or switch on extended thinking.Anything with more than one step: analysis, planning, maths, debugging.
Structured outputForce the reply into a schema so it is valid JSON every single time.Whenever a program, not a person, reads the answer.
Give it a way out"If the answer is not in the given text, say you do not know."Always. Without permission to say no, a model will make something up.
Prompt cachingMark a long unchanging opening block so you are not charged full price for it on every call.A big system prompt or reference document reused across many requests.

Summarise this customer feedback in at most three bullets.
Each bullet: the actual problem, no adjectives, no advice.
Ignore praise. If there is no real problem to act on, reply
exactly: NO ISSUES.

Prompt caching is the one cost trick worth learning early. A long set of instructions or a reference document that you send on every request can be stored by the provider, so repeat calls pay only a small fraction for that part. It matches on an exact opening block, which has one practical result: put the unchanging content first and the changing content last. Putting a timestamp at the top of your system prompt quietly kills the whole cache.

jsCaching a long prefix
const response = await client.messages.create({
  model: 'claude-opus-5',
  max_tokens: 16000,
  system: [
    {
      type: 'text',
      text: LONG_STABLE_INSTRUCTIONS,     // exactly the same on every call
      cache_control: { type: 'ephemeral' },
    },
  ],
  messages: [{ role: 'user', content: question }],   // the changing part, last
});

// Check that it is actually working:
console.log(response.usage.cache_read_input_tokens);   // zero every time = the cache is missing
Your prompt says “summarise this professionally” and the results keep changing. What is the real problem?Answer

"Professionally" is not an instruction, it is a wish. It means different things in a bank, a hospital and a startup, and the model has no way to know which one you mean.

Replace the adjective with the details you actually have in your head: how long, for whom, written in which person, what to leave out, and one example of a summary you would call correct. Output that keeps changing almost always means a half-written brief, not a weak model.
