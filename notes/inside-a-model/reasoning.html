Reasoning models and thinking time

2 min read Read the AI note first
💡
In plain English
Asked a hard question, a person does better with a pencil and a minute than answering instantly. A reasoning model is that: it generates a long internal working-out before its visible answer, and the extra tokens are where the improvement comes from. You are buying accuracy with time and money, quite literally.
txtThe same question, two behaviours
STANDARD MODEL
  prompt -> [~40 tokens of answer] -> done            fast, cheap

REASONING MODEL
  prompt -> [~3,000 tokens of working out, hidden]
         -> [~40 tokens of answer]  -> done           slow, ~10x the cost

  The working-out tokens are billed. They are usually not shown to you.
Worth the extra tokensNot worth them
Multi-step maths and logicClassification into a few known buckets
Debugging, planning a code change across filesExtraction from a document
Anything where being wrong is expensive to discoverRewriting or summarising
Ambiguous problems needing a plan firstAnything answered correctly by a cheap model already

Chain-of-thought, and the honest caveat

Asking an ordinary model to “work through it step by step” gets some of the same effect, because the intermediate tokens genuinely give the computation somewhere to happen. It is a real technique and it is cheap to try.

!
The stated reasoning is not necessarily the actual reasoning. A model can produce sound-looking steps that lead to a conclusion it would have reached anyway, and it can reach a right answer through wrong steps. Treat visible reasoning as useful evidence and a debugging aid — never as a guarantee, and never as an explanation you would put in front of a regulator. See the AI Governance note on what counts as an explanation.
Your classifier sorts support tickets into five categories. Should you upgrade it to a reasoning model?Answer

Almost certainly not. Classification into known buckets is a task cheap models do well, and reasoning tokens are pure cost on a problem with no multi-step structure to reason about. You would pay perhaps ten times as much for a difference your eval set will struggle to detect.

The decision should come from the eval set rather than from instinct in either direction. Run both, compare the scores, compare the cost, and let the numbers choose. That is what an eval set is for — see the Evaluating AI Systems note.

✓ Worth remembering
  • Text becomes tokens becomes vectors. Character-level tasks are hard because the model never sees characters.
  • Attention lets any token reach any other in one step, and its cost grows with the square of the input.
  • A Transformer is one attention block repeated many times, with residuals and normalisation holding it together.
  • The model outputs scores for the whole vocabulary; temperature and top_p decide how you pick from them.
  • Prefill is parallel and cheap, decode is sequential and expensive. Put stable text first to make prompt caching work.
  • Reasoning models buy accuracy with tokens. Let an eval set decide whether that trade pays on your task.
