How a word is actually chosen

2 min read Read the AI note first
💡
In plain English
The model never picks a word. It produces a score for all hundred thousand tokens in its vocabulary, every single time. Turning that ranked list into one choice is a separate step that you control — and the settings people treat as mysterious dials are all just different ways of deciding how far down the list you are willing to go.
txtAfter “The capital of France is”
raw scores            probabilities        after temperature 0.2
  " Paris"   14.2   ->    0.89       ->        0.997
  " located"  9.1   ->    0.06       ->        0.002
  " the"      8.4   ->    0.03       ->        0.001
  " home"     7.9   ->    0.02       ->        0.000
  ...99,996 others      ~0.00

Temperature divides the scores before ranking:
   LOW  (0.0-0.3)  gaps widen   -> the top answer nearly always wins
   HIGH (1.0-1.5)  gaps narrow  -> unlikely tokens get a real chance
SettingWhat it doesUse it when
temperatureFlattens or sharpens the whole distributionThe main dial. Low for extraction, classification and code; higher for drafting and ideas.
top_pKeeps only the most likely tokens that together make up p of the probabilityA safety net — it cuts off the long tail of nonsense that high temperature would otherwise admit. Adjust this or temperature, not both.
top_kKeeps only the k highest-scoring tokensBlunter than top_p. Rarely the better choice.
stopEnds generation when a string appearsStructured output where you know the terminator. Saves real money on long responses.
max_tokensA hard ceiling on the responseAlways set it. It is your only defence against a runaway generation.
seedMakes sampling repeatableTesting and debugging. Note it does not guarantee identical output across model versions or infrastructure.
!
Temperature 0 is not deterministic in practice. It is the closest you can get, and it is not a guarantee: floating-point arithmetic on GPUs is order-sensitive, batching changes that order, and two identical requests can diverge. Build systems that tolerate variation rather than systems that assume it away.
You are extracting an invoice total into JSON. What temperature, and why?Answer

Near zero. There is one correct answer sitting on the document, so every bit of randomness is a chance to be wrong for no benefit whatsoever. Creativity has no value in extraction.

The inverse case is worth stating too: at temperature 0 a brainstorming feature returns the same five ideas every time, and users notice quickly. The setting follows the task, and any codebase that has one global temperature for every call has almost certainly got it wrong for half of them.
