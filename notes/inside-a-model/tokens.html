Tokens: what the model actually reads

2 min read Read the AI note first
💡
In plain English
A model cannot read letters or words — it only handles numbers. So text is first chopped into pieces from a fixed vocabulary of about a hundred thousand fragments, and each piece is swapped for its number in that list. A common word is one piece. An unusual one gets broken into several. Everything odd about how models handle spelling, numbers and non-English text starts here.
txtThe same sentence, as the model sees it
"The unbelievability of it"

  ["The"] [" un"] ["bel"] ["iev"] ["ability"] [" of"] [" it"]
    976    650     6667    12776    2965      315    433

Notice: the leading SPACE is part of the token.
"cat" and " cat" are two different numbers.

What this explains

The thing that looks like a bugThe cause
“How many r's in strawberry?” answered wronglyThe model never saw the letters. It saw three tokens. Asking it to count characters is asking it to count something it cannot see.
Arithmetic on long numbers going wrong1234567 might split as 123 + 4567. Digits do not line up in columns the way they would on paper.
Hindi, Thai or Chinese costing far more than EnglishThe vocabulary was built mostly from English text, so other scripts fragment into many more tokens for the same meaning. Same sentence, several times the price.
A trailing space changing the answerIt genuinely changes the input. The token sequence is different, so the prediction is different.
JSON and code being expensiveBraces, indentation and punctuation are all tokens. Minifying a payload before sending it is a real saving.
!
Never estimate cost in words or characters. The rough rule for English is about 0.75 words per token, but it collapses for code, for other languages and for anything with heavy punctuation. Every provider ships a tokeniser you can run locally — count properly, especially before designing anything around a context limit.
A user asks your assistant to reverse the word “deterministic” and it produces something close but wrong. Is this fixable with a better prompt?Answer

Not reliably. The model is manipulating four or five tokens, not thirteen letters, so character-level work is being done indirectly at best. Chain-of-thought prompting helps a little by making it spell the word out first, which converts the problem into one it can see.

The robust fix is not a prompt at all: give the model a tool that reverses a string, or do it in your own code. This is the general shape of the lesson — when a task is a poor fit for the mechanism, route around the mechanism rather than arguing with it.
