Why this layer exists

2 min read No experience needed
💡
In plain English
Writing the app is one job. Getting it to run reliably on a machine that is not yours, every time someone pushes a change, without a person doing it by hand at 11pm, is a different job — and it has its own four tools. A virtual machine is a rentable computer. Docker packs your app and everything it needs into one box that runs identically on any of those computers. Kubernetes is the manager that keeps many of those boxes running, restarts the ones that die, and spreads them across machines. CI/CD is the conveyor belt that takes a git push and, if it passes the checks, turns it into an updated box running in production — with nobody typing a command.

Four ideas, and the confusion between them is almost always a layering problem — each one sits on top of the one before it.

LayerAnswersEveryday analogy
Virtual machineWhere does code physically run?Renting an apartment — walls, plumbing, an address. You still have to move your own furniture in.
DockerHow do I make sure it runs the same on my laptop, in CI, and in production?A shipping container — whatever is inside, the crane, the ship and the truck all handle it the same way.
KubernetesHow do I run many containers, reliably, across many machines?A shipping port's control tower — deciding which crane loads which container onto which ship, and re-routing the moment one crane breaks.
CI/CDHow does a code change become a running update, automatically?A factory conveyor belt — the part only moves forward once it has passed the inspection station.
!
You very rarely need all four, fully, on day one. Plenty of real products run happily as one Docker container on one managed platform (Cloud Run, Render, Fly.io) with a simple CI/CD pipeline and no Kubernetes and no VM you manage yourself. Kubernetes earns its complexity when you have many services, need fine control over networking and scaling, or already have a platform team to run it. Reach for it because you have that problem, not because it is the well-known name.
Where does a plain virtual machine still fit once you have Docker and Kubernetes?Answer

Underneath both of them. Every Kubernetes cluster's worker nodes are themselves virtual machines — Kubernetes does not replace VMs, it automates what runs on a fleet of them. You reach for a raw VM yourself, outside that automation, for the cases that do not fit the container model well: a box you need full OS-level control over, a GPU machine you configure by hand, or a self-hosted CI runner.
