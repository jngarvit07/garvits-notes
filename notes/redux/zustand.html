Zustand: the small one

2 min read Read React first
💡
In plain English
The same useful core — one store, and components that only re-render when the part they read changes — with the ceremony removed. What you give up is the enforced trail: anything can change state from anywhere, which is quicker to write and harder to reconstruct six months later.

Zustand takes the useful half of Redux — one store, selective subscription — and drops the actions, the reducers and the provider.

tsThe same cart, in Zustand
import { create } from 'zustand';

export const useCart = create((set) => ({
  items: [],
  add:   (p) => set((s) => ({ items: [...s.items, p] })),
  clear: () => set({ items: [] }),
}));

// In a component. No Provider anywhere in the tree.
function CartBadge() {
  // Same selective subscription as useSelector.
  const count = useCart((s) => s.items.length);
  return <span>{count}</span>;
}

function AddButton({ product }) {
  const add = useCart((s) => s.add);
  return <button onClick={() => add(product)}>Add</button>;
}

i
The trade is ceremony for traceability. Redux's boilerplate is what produces a readable, ordered history of every change. Zustand lets you call set from anywhere, which is faster to write and harder to reconstruct six months later when something sets a value and you cannot find what. Neither is wrong; they are priced differently.
When is Redux Toolkit’s extra ceremony actually worth paying for?Answer

When several people work on the codebase and you need every change to state to have a name you can read back. That ordered, reviewable history is what the boilerplate buys, and it is what makes a “the total was wrong but only sometimes” bug a five-minute job rather than an afternoon.

For a small app with one or two developers, the same discipline can be kept by convention, and Zustand’s smaller surface is the better trade. Neither is the correct answer in general — they are priced differently and you are choosing what to pay for.
