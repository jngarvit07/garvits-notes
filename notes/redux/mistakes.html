The mistakes everybody makes

2 min read Read React first
💡
In plain English
Four mistakes account for most of the trouble people have here, and none of them are subtle once named. Storing everything globally, storing a number you could have calculated, editing state in place, and writing a selector that builds something new every time.

1. Putting everything in the store

A store is not a filing cabinet for all your data. State that one component uses belongs in that component. A global store full of single-use values is harder to read than the props it replaced, and every value in it is a value you now have to remember to clear.

2. Storing what you could calculate

Not this · a total that can drift
{
  items: [...],
  total: 240,      // must be updated
                   // by every single action
                   // that touches items
}
Do this · derive it on read
{ items: [...] }

// In the selector — cannot be wrong:
const total = useSelector((s) =>
  s.cart.items.reduce((n, i) => n + i.price, 0)
);

Any value stored twice will eventually disagree with itself. If it can be computed from what you already have, compute it.

3. Mutating state outside createSlice

state.items.push(x) is correct inside an RTK slice and a silent bug everywhere else — in a plain reducer, in a Zustand set, in a useState updater. The array is the same object, so React sees no change and does not redraw. In Zustand, write set((s) => ({ items: [...s.items, x] })).

4. Selectors that return something new every time

Covered above, and worth repeating because it is the number-one cause of “Redux made my app slow”. A selector returning .filter(), .map(), or an object literal produces a new reference on every store change, so the component re-renders on every store change.

✓ Worth remembering
  • Sort state into server and client before choosing anything.
  • Lift first, Context for values that rarely change, a store only for shared client state that changes often.
  • Never store what you can derive; never mutate outside a slice.
  • Keep selectors returning primitives or stable references.
  • One client store and one server-state library is a complete architecture.
