Transforming the question first

2 min read Read the AI note first
💡
In plain English
People do not ask questions in the form documents are written in. They say “what about the second one?”, or ask two things at once, or use their own words for something your documentation calls something else. A short, cheap model call that rewrites the question into a good search query fixes all three, and it is one of the least appreciated steps in the pipeline.
TechniqueWhat it doesFixes
ContextualiseRewrite a follow-up into a standalone question using the conversation“And for annual plans?” retrieving nothing. Essential for any chat interface.
DecomposeSplit a multi-part question into separate searches“How do refunds and cancellations differ?” — two topics, one query, neither retrieved well
ExpandGenerate two or three phrasings and search with all of themVocabulary mismatch between how users speak and how documents are written
HyDEHave the model write a hypothetical answer, then search using thatShort queries. An answer-shaped text matches answer-shaped chunks better than a question does.
Extract filtersPull dates, names, types out of the question into metadata filters“invoices from last March” being answered semantically rather than by date
tsContextualising a follow-up — the one to implement first
// Without this step, turn 2 searches for the literal words
// "and for annual plans?" and retrieves nothing useful.
const standalone = await cheapModel({
  system: `Rewrite the user's latest message as a standalone question,
resolving every pronoun and reference from the conversation.
Output ONLY the rewritten question, nothing else.`,
  messages: [...lastThreeTurns, latest],
});

//  history: "What is the refund window for monthly plans?"
//  latest:  "and for annual plans?"
//  ->       "What is the refund window for annual plans?"

const hits = await hybridSearch(standalone, { filter: { orgId } });
i
Use a small, fast model for this. It is a mechanical rewriting job, it runs on every single question, and it sits directly in the latency path. Spending your capable model on it buys nothing measurable and costs you on every request.
Your chat assistant answers the first question well and then falls apart on follow-ups. What is almost certainly missing?Answer

Query contextualisation. The first question is self-contained, so it searches well. The second is “what about enterprise?” — which as a search query means nothing, retrieves noise, and the model then answers from noise.

This is the single most common reason a RAG demo that looked excellent falls over in a real conversation, and it is perhaps twenty lines to fix.
