Hybrid search: the highest-value upgrade

2 min read Read the AI note first
💡
In plain English
Vector search finds things that mean the same. Keyword search finds things that say the same. Each is blind where the other sees: ask for “error P0420” and vector search happily returns passages about other error codes, because they are all semantically similar. Running both and merging the results fixes a whole category of failure at once.

tsReciprocal Rank Fusion — combining two ranked lists
// The elegance here: RRF uses each result's RANK, not its score.
// That matters because a cosine similarity of 0.82 and a BM25 score
// of 14.3 are not on the same scale and cannot be sensibly added.
function fuse(lists: string[][], k = 60): string[] {
  const score = new Map<string, number>();

  for (const list of lists) {
    list.forEach((id, rank) => {
      // Position 0 contributes 1/61, position 1 contributes 1/62 ...
      score.set(id, (score.get(id) ?? 0) + 1 / (k + rank + 1));
    });
  }

  return [...score.entries()]
    .sort((a, b) => b[1] - a[1])
    .map(([id]) => id);
}

const merged = fuse([
  vectorSearch(embed(q), { k: 50, filter: { orgId } }),
  keywordSearch(q,        { k: 50, filter: { orgId } }),
]);
// Something both searches liked rises to the top. Something only one
// found still appears — which is exactly the behaviour you want.
i
You very likely already have both halves. Postgres does full-text search natively and vector search through pgvector — so hybrid retrieval is two queries against one database you already operate. Adding a separate vector service before you have exhausted this is a common and expensive detour. See the PostgreSQL & Prisma note.
Why fuse on rank rather than just adding the two similarity scores together?Answer

Because the two scores measure different things on different scales. Cosine similarity is bounded roughly between 0 and 1 and clusters tightly; BM25 is unbounded and depends on corpus statistics. Adding them lets whichever number happens to be larger dominate, which is arbitrary rather than meaningful.

Rank is scale-free. “Third best according to keyword search” is comparable to “third best according to vector search” in a way the raw numbers are not, and RRF needs no tuning per corpus — which is why it is the default worth starting from.
