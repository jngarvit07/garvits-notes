The five layers every AI feature has

2 min read Some experience helps
💡
In plain English
Every AI feature has the same five layers whether or not anyone drew them. Naming them gives you the most useful diagnostic question there is: when something goes wrong, which layer was it? Teams that cannot answer that end up rewriting prompts to fix retrieval problems.

Every AI system, from a weekend prototype to a product with a compliance team, has the same five layers. You do not choose whether to have them; you only choose whether they are deliberate.

Layer 3 is where quality lives

Almost every “the AI gave a bad answer” bug is a context bug: the right passage was not retrieved, the history was truncated, the system prompt did not mention a rule. Fix context before you touch the prompt wording.

Layer 4 is where risk lives

A model that can only read is a quality problem when it is wrong. A model that can write, send, pay or delete is an incident. Every capability you add multiplies the consequence of every context bug.

!
The single most useful diagnostic question: when something goes wrong, which layer was it? Teams that cannot answer this end up rewriting prompts to fix retrieval bugs, and swapping models to fix orchestration bugs. Logging enough to answer it — see the AI Ops note — is worth more than any framework.
A support bot confidently states a refund policy that was changed last month. Which layer failed?Answer

Layer 3, context — almost certainly. Either the retrieval index still holds the old policy document, or it holds both and the old one ranked higher. Neither the model nor the prompt is at fault, and changing either would be a plausible-looking action that fixes nothing. The repair is in the indexing pipeline: how documents get in, and how superseded ones get out.
