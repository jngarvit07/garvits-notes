Connecting it up

2 min read Some experience helps
💡
In plain English
Connecting a server is a small configuration file telling the host how to start it and what it needs. This is also the step where most first attempts fail, almost always for the same two reasons: the path is wrong, or an environment variable the server needs was not passed through.

To Claude Code, or any local host

A JSON file naming the command to run. Project-scoped config lives in .mcp.json at the repository root, which means the server travels with the codebase and every developer gets it.

json.mcp.json
{
  "mcpServers": {
    "invoices": {
      "command": "node",
      "args": ["./mcp/invoices/dist/index.js"],
      "env": {
        "DATABASE_URL": "${DATABASE_URL}"
      }
    }
  }
}

From the API, as a connector

A remote MCP server can be attached directly to a Messages request. Note the shape carefully — both halves are required, and supplying only the first is the single most common mistake here.

tsattaching a remote MCP server to a request
const response = await client.beta.messages.create({
  model: 'claude-opus-5',
  max_tokens: 16000,
  betas: ['mcp-client-2025-11-20'],

  // Half one: where the server is.
  mcp_servers: [
    { type: 'url', url: 'https://tools.example.com/mcp', name: 'invoices' },
  ],

  // Half two: permission to use it. Omit this and the request is REJECTED as a
  // validation error — the name must match the server above exactly.
  tools: [{ type: 'mcp_toolset', mcp_server_name: 'invoices' }],

  messages: [{ role: 'user', content: 'What did ACME buy in March?' }],
});
!

Declaring mcp_servers without the matching mcp_toolset entry fails validation rather than silently doing nothing — which is the kinder failure, but the error message does not always make the cause obvious. If a connector request is rejected and the URL looks right, check that the name matches on both sides.
