Routing by folder

2 min read Some experience helps
💡
In plain English
In most frameworks you keep a list somewhere saying “this address shows that page”. Next.js throws the list away and uses your folders instead: the folder path is the web address. A folder called settings with a page in it is the /settings page. Nothing to register, nothing to keep in sync, and the shape of the site is visible in the file tree.

A folder under app/ is a URL segment; a page.tsx inside it makes that URL real. Nothing is registered anywhere. The file tree is the routing table, which means you can read the whole site’s map with ls.

tsxThis product, abbreviated
app/
  page.tsx                      ->  /
  dashboard/page.tsx            ->  /dashboard
  admin/
    layout.tsx                  ->  wraps everything under /admin
    overview/page.tsx           ->  /admin/overview
    learning/
      page.tsx                  ->  /admin/learning
      react/page.tsx            ->  /admin/learning/react
    users/
      page.tsx                  ->  /admin/users
      [userId]/page.tsx         ->  /admin/users/anything

The filenames that mean something, and only these:

FileWhat it is
page.tsxThe screen for this URL. Without one, the folder is just a path segment nobody can visit.
layout.tsxChrome wrapped around this folder and everything under it. Survives navigation between children — it does not re-mount.
loading.tsxShown automatically while this route is being prepared.
error.tsxShown when the route throws. Must be a Client Component, and receives a reset() to try again.
not-found.tsxShown for notFound() and unmatched URLs.
route.tsAn HTTP endpoint instead of a screen. Cannot live in the same folder as a page.tsx.
[id]/A dynamic segment: matches anything, and hands you the value.
(group)/A folder purely for organisation. The parentheses keep it out of the URL.

Navigation between routes uses <Link>, not <a>. A plain anchor reloads the whole application — the JavaScript, the styles, the auth state, all of it — while Link fetches only what the next screen needs and swaps it in. Use <a> only for genuinely external addresses.

tsNavigating
import Link from 'next/link';
import { useRouter, usePathname, useSearchParams } from 'next/navigation';

<Link href="/admin/users">Users</Link>

// Navigating from code — after a save, say.
const router = useRouter();
router.push('/admin/users');
router.refresh();     // re-fetch the current route's server data, keeping local state

// Where am I?
const pathname = usePathname();                        // "/admin/users"
const page = useSearchParams().get('page');            // "?page=2" -> "2"
You create app/pricing/page.tsx. What is the URL, and what would you have had to do in a framework without folder routing?Answer

/pricing, and nothing else. In a framework with a route table you would also have to add an entry mapping that path to that component, and remember to remove it when the page goes. The commonest bug that removes is a route table that has drifted from the files it points at.
