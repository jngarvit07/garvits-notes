Environment variables and deploying

2 min read Some experience helps
💡
In plain English
Some values differ between your laptop and the live site — a database address, an API key. They live outside the code in environment variables, so the same code runs in both places. The rule that matters: anything the browser can see is public. In Next.js, a variable is only sent to the browser if its name starts with NEXT_PUBLIC_, which makes that prefix a decision rather than a convention.

Environment variables keep configuration out of the code. In Next there is one rule that matters more than all the others:

!
NEXT_PUBLIC_ means public. A variable with that prefix is baked into the JavaScript sent to every browser. Anything without it stays on the server. A secret given that prefix — an API key, a database URL — is published the moment you deploy, and rotating it is the only fix.
jsfrontend/.env.local
# Readable by the browser. Only ever put non-secrets here.
NEXT_PUBLIC_API_URL=http://localhost:5000/api/v1

# Server-side only. Never reaches the browser.
INTERNAL_WEBHOOK_SECRET=...

Also worth knowing: these values are read at build time for client-side variables, not at boot. Changing one on a hosting dashboard does nothing until the next deployment — a genuinely confusing hour if you have not met it before.

Deployment is next build followed by next start, or a platform that does both for you. This frontend deploys to Vercel; the Express API deploys separately, which is why NEXT_PUBLIC_API_URL exists at all.

You add your model provider’s API key as NEXT_PUBLIC_MODEL_KEY so a client component can use it. What have you just done?Answer

Published it. That prefix means the value is baked into the JavaScript sent to every visitor, so anyone can open devtools and read it. It is now spendable by strangers and must be rotated.

The fix is structural, not a rename: the browser should call your route handler, and your server — holding the unprefixed key — calls the provider. A secret that reaches the browser was never a secret.
