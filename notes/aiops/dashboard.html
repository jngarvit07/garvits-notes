The dashboard, and the alerts

2 min read Some experience helps
💡
In plain English
Four numbers tell you the system is running: volume, latency, failures and cost. None of them would move at all if every answer became subtly wrong tomorrow. That is why a fifth panel — some measure of whether the answers are any good — is the one that separates monitoring an AI system from monitoring a normal one.

Resist the instinct to graph everything. A dashboard with forty panels is a dashboard nobody reads.

1. Volume, by feature

Calls per minute, split by feature. Everything else is read relative to this line — cost is only alarming if volume did not explain it.

2. Latency, p50 and p95

Both, always. And for anything streamed, time-to-first-token separately from time-to-complete, because they diverge and users feel the first.

3. Failure rate, by kind

Not one number. Split: provider errors, timeouts, invalid output shape, refusals, guardrail blocks. Each has a completely different cause and fix.

4. Cost per request

Tokens in and out per call, multiplied out, split by feature. A rising line here with flat volume means your prompts or your context grew.

The fifth panel most dashboards do not have

A quality signal. The four above tell you the system is running. None of them would move at all if every answer became subtly wrong tomorrow. You need at least one of:

SignalHonestyEffort
Thumbs up / downLow volume, biased towards the angry — but the trend is realAn afternoon
Implicit signalsGood. Did they copy it, retry, rephrase, escalate to a human, abandon?A day, and worth it
A scheduled eval runBest. The same cases every hour against production, scored automaticallyYou have already built the eval set — just run it on a schedule
Sampled human reviewThe ground truth everything else is calibrated againstAn hour a week, and it is the hour that catches what nothing else does

What is worth waking someone for

Page immediatelyLook at it tomorrow

The feature is returning nothing at allCost per request up 15%

Guardrail blocks spiking — someone is probing youOne user reporting one bad answer
!
Alert on cost. It is the one metric where a bug is silently expensive rather than visibly broken: a retry loop, an accidentally unbounded agent, or a prompt that started including a whole document. Everything else fails in a way somebody notices; this one just arrives as an invoice.
