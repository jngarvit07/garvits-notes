Tracing a request through the whole chain

2 min read Some experience helps

A single user question might embed a query, search a vector index, rerank, call a model, call two tools, and call the model again. When it takes eleven seconds, a log line per step in six different places will not tell you why.

💡
In plain English
A parcel tracking page. You do not want six separate emails from six depots — you want one page showing the whole journey, where it waited, and for how long. A trace is that page for one request, and each stop is a span.

Without the trace, the obvious move is to switch to a faster model — a change that would have saved perhaps a second and a half and cost you quality. With it, the answer is a reranker on a warm instance, or fewer candidates.

tsSpans, using OpenTelemetry conventions
// A trace id is created at the edge and passed down through everything.
// It is the join key for your entire system.
await tracer.startActiveSpan('rag.answer', async (span) => {
  span.setAttribute('feature', 'support_reply');

  const hits = await tracer.startActiveSpan('vector.search', async (s) => {
    const r = await index.search(vec, { k: 20, filter: { org: orgId } });
    s.setAttribute('result_count', r.length);
    return r;
  });

  const answer = await tracer.startActiveSpan('llm.call', async (s) => {
    const r = await complete({ prompt, context: hits });
    s.setAttribute('tokens_in', r.usage.in);
    s.setAttribute('tokens_out', r.usage.out);
    return r;
  });

  span.setAttribute('chunk_ids', hits.map((h) => h.id).join(','));
  return answer;
});
i
Use OpenTelemetry rather than a vendor's SDK directly. It is the open standard, every observability backend accepts it, and it means the tool you send traces to is a configuration change rather than a rewrite. The same reasoning as putting your model calls behind one wrapper.
Users report the assistant is slow, but your dashboard shows a p50 of 1.8s. What is the most likely explanation?Answer

You are looking at the median, and half your users are above it. In AI systems the tail is unusually long — a request that retrieves more, generates more, or takes an extra tool step can be five times the median. Look at p95 and p99. Also check whether “latency” means time-to-first-token or time-to-complete: with streaming those are very different numbers, and the one users feel is the first.
