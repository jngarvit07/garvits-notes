Evaluating RAG and agents specifically

2 min read Some experience helps

RAG: score retrieval and generation separately

This is the single most useful idea in this note. Almost every disappointing RAG system fails at retrieval and gets blamed on the model — and one combined score cannot tell you which half is broken.

StageQuestionHow to score it
RetrievalDid the chunk containing the answer come back at all?Mark the correct chunk id per case; check whether it appears in the top k. Programmatic, exact, no judgement needed.
GroundingIs every claim in the answer supported by what was retrieved?A judge, with the retrieved context in front of it. Binary, per claim.
RefusalWhen the answer genuinely is not in the corpus, does it say so?Cases with no answer, and an exact expected refusal. This one catches the failure that damages trust most.
Answer qualityIs it actually useful to a person?A judge with a rubric — only meaningful once the three above pass.
💡
In plain English

If retrieval scores 60%, no prompt engineering will save you — the answer was never in the room. Fix the search before you touch the wording. Teams routinely spend weeks on the prompt for a retrieval bug.

Agents: score the trajectory, not just the ending

An agent can reach the right answer through twelve wasteful steps, or reach a wrong one having done everything sensibly. Only scoring the final output hides both.

What to measureWhy it matters
Task success — did it achieve the goal?The headline number, but on its own it is not diagnostic.
Steps takenA rising step count is the earliest signal that something in the tool set has become confusing.
Tool choice accuracyDid it pick the right tool at each decision point? This localises the fault to a description you can rewrite.
Tokens and cost per runThe thing that quietly ruins the economics. Track per run, not per request.
Gate hitsHow often it attempted something requiring approval. A sudden rise is worth investigating immediately.
