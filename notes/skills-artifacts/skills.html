Skills: instructions that load themselves

4 min read No experience needed
💡
In plain English
A skill is a written set of steps that loads itself the moment it becomes relevant, instead of sitting in the prompt all the time and taking up space. Think of a rack of instruction cards on a wall: the model reaches for the one card that matches the job, instead of carrying all of them everywhere.

A skill is just a folder. At the top of it sits a SKILL.md file whose header carries a name and a one-line description. Below that is whatever the task needs — longer instructions, reference documents, scripts, templates.

What makes it useful is that it opens up in stages. Only the one-line description sits in the context all the time. The model reads the full file — and any files that file points to — only when a task actually needs it.

mdskills/invoice-review/SKILL.md
---
name: invoice-review
description: >
  Review a supplier invoice against our purchase-order rules before it is
  approved for payment. Use whenever someone asks to check, review, or approve
  an invoice, or asks whether an invoice looks right.
---

# Reviewing a supplier invoice

Work through these in order. Stop at the first hard failure and say which.

1. **Match the PO.** Every line must map to a line on the referenced purchase
   order. A line with no PO line is a hard failure — never "probably fine".
2. **Check the totals.** Recompute from the line items. Do not trust the stated
   total; the whole point of this check is that it is sometimes wrong.
3. **Check the tax treatment** against `reference/tax-rules.md`. Read that file
   only when the supplier is outside the UK — domestic invoices never need it.
4. **Flag anything over £10,000** for a second human approver, regardless of
   whether it passes everything else.

## Output

A short verdict — `approve`, `query`, or `reject` — then the reasons as bullets.
Quote the invoice line number for every problem. Never approve with unresolved
queries; "approve with caveats" is not one of the three options.

## What not to do

- Do not contact the supplier. That is a person's decision, not this task's.
- Do not adjust figures to make them match. Report the mismatch.

What makes a skill good

RuleWhy
The description is a trigger, not a summary. Say when to use it, using the words a real person would actually type.It is the only part that is always in the context. If it does not match the way people word the request, the skill never loads and everything below it is wasted effort.
Write the steps, not the background. What to do, in what order, and where the decisions are.The model already knows what an invoice is. What it does not know is that your team always recalculates the total.
Say what not to do.Telling it what not to do is what prevents the confident, believable, wrong action — and that is the failure that actually costs you money.
Push the detail into separate files.It keeps the always-read part short, and keeps the rarely-needed reference out of the context until the day it matters.
One skill, one job.A skill that covers “finance tasks” matches everything and helps with nothing.

Using skills from the API

On the Messages API, skills run inside the code-execution container, so you switch them on through container next to the code-execution tool. This is the route that produces real .pptx, .xlsx or .docx files.

tsa skill that produces a real file
const response = await client.beta.messages.create({
  model: 'claude-opus-5',
  max_tokens: 16000,
  betas: ['code-execution-2025-08-25'],

  // Which skills are available inside the container for this request.
  container: {
    skills: [{ type: 'anthropic', skill_id: 'pptx', version: 'latest' }],
  },

  // Skills execute via code execution — both parts are needed.
  tools: [{ type: 'code_execution_20260521', name: 'code_execution' }],

  messages: [{ role: 'user', content: 'Build a 3-slide deck summarising Q3 revenue.' }],
});

Agent Skills are not the same thing as Managed Agents. Both have the word “agent” in them and they are completely different things. Skills go through container on an ordinary Messages call, as shown above. Managed Agents is a separate product where Anthropic runs the loop and hosts a workspace for the session. Reaching for client.beta.agents to make a PowerPoint is a wrong turn that costs you an afternoon.

Your model keeps producing correct figures in the wrong report format, no matter how much you add to the system prompt. Skill, tool, or RAG?Answer

A skill. The facts are right, so retrieval is not the missing piece; nothing needs doing, so a tool is not it either. What is missing is the method — your format, your order of sections, your conventions — and that is exactly what a skill carries.

The reason the system prompt is not working is usually that it is too long. Formatting rules added there have to compete with everything else for attention, on every single request. In a skill they arrive as one focused, relevant instruction at the exact moment the task needs them.
