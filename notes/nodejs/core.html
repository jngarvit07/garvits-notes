The built-in toolkit

2 min read No experience needed
💡
In plain English
Node arrives with a toolbox: reading files, making network requests, working with paths, hashing, compressing. Knowing what is already there stops you installing a package for something that is one line of built-in code — and every package you do not install is one less thing to update, audit and trust.

Node ships with modules you never install. The ones worth recognising:

ModuleForTypical use
fsFilesAlways the fs/promises version inside a request.
pathBuilding file pathspath.join(dir, name) — never string concatenation, or Windows breaks.
httpA web server, at the lowest levelWhat Express is built on top of.
cryptoHashing, random values, signingcrypto.randomUUID(), secure random tokens.
eventsThe emit/listen patternUnderneath streams, sockets, and much of the ecosystem.
urlParsing URLs and query stringsReading parameters without regular expressions.
osThe machineCPU count, temp directory, memory.
tsThings you will actually type
import { randomUUID, randomBytes, createHash } from 'node:crypto';
import path from 'node:path';
import fs from 'node:fs/promises';

const id = randomUUID();                                   // an id for a new row
const token = randomBytes(32).toString('hex');             // an unguessable token
const fingerprint = createHash('sha256').update(body).digest('hex');

const target = path.join(process.cwd(), 'uploads', name);  // safe path building

Never use Math.random() for anything security-related. It is fast and predictable — fine for shuffling, useless for a password-reset token, an invitation code or a session id. crypto.randomBytes and crypto.randomUUID exist for exactly this.
