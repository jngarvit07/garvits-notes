The ladder: start at the bottom

2 min read Some experience helps
💡
In plain English
There is a ladder from “ask the model once” to “let the model decide what to do next, repeatedly”. Every rung buys capability and costs predictability. The discipline is to start at the bottom and climb only when the rung you are on has visibly failed at the actual job — not when the one above sounds more impressive.

There are four rungs between “one API call” and “an agent”. Each is cheaper, faster and easier to reason about than the one above it. Climb only when the rung you are on genuinely cannot do the job.

Four questions before you build an agent

Complexity

Is the task genuinely hard to specify up front? “Turn this design doc into a pull request” qualifies. “Pull the title out of this PDF” does not.

Value

Does the outcome justify several times the cost and latency of a single call? An agent that saves ten minutes of your time is worth it; one that saves ten seconds is not.

Viability

Is the model actually good at this class of task today? Test on twenty real cases before you build infrastructure around the answer.

Cost of error

Can a mistake be caught and undone — by tests, review, a rollback? An agent that can send money or delete rows without a gate is a liability, not a feature.

A “no” to any one of those means stay on a lower rung.
