Building one on this stack

2 min read Some experience helps
💡
In plain English
What building one on this stack actually looks like — where the loop lives, where the tools live, and what the limits are set to.

Nothing here needs a framework. The pieces map onto what notes 03 and 04 already covered.

The loop belongs on the server

An agent loop in the browser ships your API key to a stranger. It runs in Express, behind auth, exactly like any other route that touches money.

Tools are just functions you already have

Your existing service functions are the tools. Wrap them with a schema and a description; do not write a second implementation for the agent.

Long runs outlive the request

An agent that takes two minutes cannot live inside an HTTP handler. Start a job, return an id, stream progress — the same shape as any long task.

Traces are rows

You already have Postgres. One row per step, indexed by run id, is a better observability story than most purpose-built tools give you.

▶
Practice

Build the smallest real agent: two tools — list_files and read_file, both scoped to one directory — and the task “find where X is configured in this project and explain it”. Cap it at eight steps.

Then break it deliberately. Make read_file throw on one path and watch what the model does with the error. Change the error message from a stack trace to a sentence and watch it recover instead. That single experiment teaches more about tool design than any amount of reading.

Finally, log every step to a file and read the trace end to end. You will find at least one step you did not expect.

✓ Worth remembering
  • An agent is a loop where the model chooses the next step. If you can draw the flowchart, write the flowchart instead.
  • The model never executes anything — it asks. Everything you can control sits between the asking and the doing.
  • Your tool descriptions are your real prompt. Say when not to use each tool, not just what it does.
  • Send all results from one turn back in a single user message, and never drop a failed one — mark it is_error.
  • Iteration cap, cost budget, approval gates. An agent without exit conditions is an outage waiting for a quiet weekend.
  • Prompts are files. Tools are files. Evals live next to them. Anything worth reviewing gets a diff.
