A folder structure that survives contact

2 min read Some experience helps
💡
In plain English
Agent code degenerates into one enormous function faster than most code, because everything is genuinely connected to everything. Separating the loop, the tools, the prompts and the limits into their own places is what keeps it possible to change one without breaking the others.

Agent code sprawls faster than ordinary code, because prompts, tool implementations, schemas and evaluation data all want to live somewhere and none of them are obviously “source”. This layout has one rule behind it: anything you would want to diff in a review gets its own file.

i

Why prompts are files and not string literals. A prompt is the highest-leverage, most-frequently-edited artefact in the whole system. As a .md file it gets reviewed, blamed, and reverted like anything else. Buried in a template literal three levels deep, it gets edited by whoever is nearest and nobody notices the regression for a week.

Real worldWhy tools/index.ts is a single registry

Assembling the tool array in one place sounds like bureaucracy until the first incident. When the tool list is built inline at three different call sites, nobody can answer “what could this agent actually do at 4pm on Tuesday?” — and that is precisely the question a security review, a bug report and an audit all ask.

It also protects your cache. The tool block is rendered first, so a tool list assembled in a different order per request invalidates the cached prefix on every single call. One registry, one order, one cache.
